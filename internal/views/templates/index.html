API Observer

Overview

API Observer is a self-hosted API observability platform that monitors and evaluates HTTP traffic against OpenAPI contracts and custom security rules. It produces structured findings that help developers identify unexpected behavior, contract violations, and potential security concerns.

API Observer observes traffic without sitting directly in the request path. Instead, an application uses the API Observer SDK to copy completed HTTP exchanges and send them asynchronously to the Observer service.

How it works

  1. The application receives a request.

    The API Observer SDK captures a copy of the HTTP request and response.

  2. The exchange is sent asynchronously.

    The SDK sends the copied exchange to the API Observer ingestion endpoint without delaying the application's response.

  3. The exchange is evaluated.

    API Observer compares the traffic against the application's OpenAPI document and configured host rules.

  4. Findings are generated.

    Contract violations, suspicious values, missing headers, unexpected fields, and other rule matches are recorded as structured findings.

  5. Results are stored for review.

    Audit results and findings can be reviewed locally or forwarded to other monitoring and security systems.

Design goals

  • Observe API behavior without blocking application traffic.
  • Validate real traffic against documented API contracts.
  • Support application-specific security and policy rules.
  • Keep SDK integration small and straightforward.
  • Produce findings in a structured, machine-readable format.

Quick Start

Clone the project and start the Observer service:

git clone https://github.com/Iztuk/api-observer.git
cd api-observer
go run ./cmd/observer

Verify that the service is running:

curl http://localhost:8080/health

Architecture

API Observer is organized around a small set of components that separate traffic capture from audit processing.

Application SDK

Middleware captures a copy of the incoming request and outgoing response. The original application request continues normally.

Observer service

The service receives API exchange events through its ingest endpoint and creates audit jobs for processing.

Rule engine

The rule engine evaluates API exchanges against OpenAPI requirements and custom host-specific rules.

Log store

Jobs and audit findings are stored as JSON Lines records for later analysis.

SDK

API Observer provides an SDK for capturing HTTP requests and responses and sending them asynchronously to the Observer service.

Go

Install

go get github.com/Iztuk/go-observer-sdk

Usage

package main

import (
    "log"
    "net/http"

    observer "github.com/Iztuk/go-observer-sdk"
)

func main() {
    mux := http.NewServeMux()

    mux.HandleFunc("GET /health", func(
        w http.ResponseWriter,
        r *http.Request,
    ) {
        w.WriteHeader(http.StatusOK)
        w.Write([]byte("healthy"))
    })

    handler := observer.Middleware(
        observer.APIObserverConfig{
            Endpoint: "http://localhost:8080/events",
        },
    )(mux)

    log.Fatal(http.ListenAndServe(":8081", handler))
}

Captured data

  • HTTP method
  • Request URL
  • Request headers and body
  • Response status code
  • Response headers and body

Events are sent asynchronously so the application does not need to wait for API Observer to process the exchange.

Event Ingestion

The Observer server exposes an endpoint for receiving captured HTTP exchanges from registered clients. 

POST /events
Content-Type: application/json
X-Observer-SDK: true

After receiving an event, the service can store a job record and pass the exchange to the rule engine.

Auditing

OpenAPI

API Observer can register an OpenAPI document for an application and compare observed traffic against that contract.

OpenAPI auditing can detect problems such as:

  • Undocumented paths or methods
  • Unexpected response status codes
  • Missing response bodies
  • Invalid response body formats
  • Schema validation failures
  • Unexpected content types

Custom Rules

Custom host rules allow API Observer to detect behavior that may not be represented by an OpenAPI document.

Rules can match request or response properties such as:

  • Paths and HTTP methods
  • Query parameters
  • Headers
  • Content types
  • JSON fields
  • Regular expression patterns
rules:
  request.query.debug_enabled:
    enabled: true
    applies_to:
      - request
    type: query
    description: Detects requests that enable debug mode.
    match:
      paths:
        - "*"
      methods:
        - GET
        - POST
      query_params:
        debug:
          - "true"
    finding:
      title: Debug query parameter enabled
      message: Request included debug=true in the query string.

Findings

When an exchange violates an OpenAPI requirement or custom rule, API Observer creates an audit finding.

A finding may include:

  • A finding title
  • A human-readable message
  • The affected host and path
  • The request ID
  • The matching rule
  • The observed request or response metadata
  • A timestamp

Storage

API Observer currently supports structured JSON log storage for jobs and audit findings.

Each object is written as a single JSON record on its own line, making the files easy to inspect or ingest into another observability platform. 

API_OBSERVER_JOB_LOG_STORE=/var/log/observer/job.jsonl
API_OBSERVER_FINDINGS_LOG_STORE=/var/log/observer/audit.jsonl

Configuration

API Observer can be configured through environment variables and registration files.

Typical configuration includes:

  • The Observer server address
  • The event ingestion endpoint
  • The OpenAPI document path
  • The host rules path
  • The job log path
  • The findings log path
API_OBSERVER_ADDR=:8080
API_OBSERVER_JOB_LOG_STORE=/var/log/observer/job.jsonl
API_OBSERVER_FINDINGS_LOG_STORE=/var/log/observer/audit.jsonl
